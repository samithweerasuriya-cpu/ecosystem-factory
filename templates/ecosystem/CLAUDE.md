## 1. Hard boundaries

You MUST NOT:
- write or edit content artifacts (drafts, reviews, the final output): agents produce them;
- fix an agent's output yourself, ever; invalid output is re-asked once, then recorded as `infra_error`;
- review or approve anything, or run `engine/gate.py` (human-only; the hook blocks it);
- edit `jobs/*/state.json`, run logs or gate files: use `engine/state.py` only;
- read `.env` files or keys, push to Git, or call MCP tools (none are allowed in this ecosystem);
- carry decisions in your head between steps: re-read `engine/state.py status <job>` before every step.

## 3. The job loop

Start a job with `/new-job` and run it with `/run-job <job_id>`. For each step:

1. `.venv\Scripts\python.exe engine\state.py status <job>`: read `state`, `stage`, `artifact_path`, `counters`.
2. Act on the state:

| State | Your action |
|---|---|
| PLANNED | `state.py event <job> dispatch` |
| WORKING | Run the agent named in `stage`: `engine\agent_call.py job <job> .claude\agents\<stage>.md`. The script checks the answer, re-asks once if it is invalid, and records any failure itself (`infra_error`). On success it prints `saved <path>`: then `artifact_ready --artifact <path>`. |
| REVIEW | Run the reviewer the same way; the script has already checked its findings (schema, severity lock, IDs). Read the saved file's verdict: `review_pass` or `review_fail`. |
| REVISING | Run the agent in `stage` the same way; it receives the latest findings and its answer is saved as the next version. Then `revised --artifact <saved path>`. |
| AWAITING_INPUT | Relay the agent's questions to the approver word for word; record the answers with `state.py input <job> <file>`, then `answered`. |
| GATE | Stop. Report to the approver (section 6). Do nothing else for this job. |
| APPROVED | `complete`. |
| BLOCKED / ESCALATED | Stop. Report (section 6). Only `resume` after the approver explicitly says so. |
| DONE / CANCELLED | Report the outcome and stop. |

3. Exit code 3 from `state.py` means a cap or the usage ceiling was hit and the job is paused. Stop and report.

## 4. Handoffs

The engine builds every handoff by script (`state.py handoff <job>`); `agent_call.py job` sends it. Never write or
change a handoff yourself. An agent's output is only the structured object its schema names. The script saves
each valid answer with its fingerprint; never edit, rewrite or repair a saved answer (every later step re-checks the
fingerprint and refuses a changed file), and never open the `rejected/` folder's answers as input.

## 5. Routing rules

1. Never skip the review. The author never reviews its own work.
2. Reviewers get the artifact, the rules and the approver's own inputs, never the author's reasoning.
3. If a reviewer contradicts a severity the approver set, re-ask that reviewer once quoting the directive; never
   change the findings yourself.
4. Missing information becomes a question for the approver, never an assumption.

## 6. Talking to the approver

At GATE, BLOCKED or ESCALATED, use this format:
```
JOB <id> is at <STATE>.
What happened: <1-2 lines>
Read first: <artifact path>, <findings path>
Options: approve | reject with feedback | cancel        (GATE)
         resume | revise scope | cancel                (BLOCKED/ESCALATED)
To approve, run in YOUR terminal: .venv\Scripts\python.exe engine\gate.py approve <id>
To reject:                         .venv\Scripts\python.exe engine\gate.py reject <id> --feedback "..."
```
